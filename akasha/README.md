# akasha

場の化石化 — 「今」を構成する情報を、その時その時で記録し、地層として積み上げるリポジトリ。

## 思想

場(祭壇・存在・波動・エネルギー・観測者自身)のすべてが揃って「限りなく一瞬に近い今」の運命が決まる。
ならば、場を構成する情報を観測できる限り記録し続ければ、過ぎ去った一瞬は化石として残る。

- **復元できるもの**(天体位置・暦)は座標軸。タイムスタンプから再計算できる
- **復元できないもの**(天気・地磁気・観測者の状態・偶発の出目)が真の化石化対象
- 記録は**追記のみ**。過去のスナップショットは絶対に書き換えない。コミットが封印

## 構成

```
definitions/   # 定義データ(祭壇・場所の象徴・占術体系) — 手動、変更時のみ
field/         # 場のスナップショット — 自動、3時間ごと(UTC 0,3,6,...時)
acts/          # 儀式・占いの記録 — 手動、行為ごと
schemas/       # field / act のJSON Schema
scripts/       # 収集スクリプト
worker/        # 位置→象徴の翻訳所(Cloudflare Worker、Overland受け口)
```

## 場所の象徴方式

生座標は化石に混ぜない。場所は `definitions/sites.json` の**象徴名**でのみ記録する。

- 公開ランドマーク(例: 皇居)は座標ごと辞書に置いてよい
- 個人的な場所(自宅の祭壇など)の座標は、リポジトリではなく
  GitHub Actionsのシークレット `SITES_JSON` / Workerのシークレットにだけ置く。
  `SITES_JSON` が設定されていれば `definitions/sites.json` より優先される
- 辞書のバックアップはパスワードマネージャ等、Git外の安全な場所に

## 自動収集(field層)

`.github/workflows/collect.yml` が3時間ごとに `scripts/collect.py` を実行し、
`field/YYYY/MM/DD/HHMMZ.json` を1ファイル追加してコミットする。

| 項目 | ソース |
|---|---|
| 地磁気 Kp指数・太陽風・惑星間磁場 | NOAA SWPC (公開API・認証不要) |
| 気温・気圧・湿度・雲量・風・降水 | Open-Meteo (公開API・認証不要) |
| 太陽〜冥王星+月の黄経・月相・月齢 | ローカル計算 (astronomy-engine) |
| 二十四節気・日の干支・曜日の惑星 | ローカル計算 |

APIが落ちていても化石化は止めない — 取れなかった項目は `null` +エラーメモで残す。

## 運用構造 (push / deploy)

`main` が地層の本体。3本のワークフローが守る:

| ワークフロー | トリガー | 役割 |
|---|---|---|
| `collect-field` | 3時間ごと + 手動 | スナップショット生成 + **STRATA.md(地層確認ページ)再生成** → botが `main` に追記コミット |
| `validate` | 全push / PR | field・actsの全レコードをスキーマ検証。壊れたデータの混入を即検知 |
| `deploy-worker` | `worker/**` 変更時 | akasha-gateをCloudflareに自動デプロイ(シークレット未設定なら静かにスキップ) |

push規約:
- **field/** はbot専用。人間は触らない(過去の書き換え禁止 = 追記オンリー)
- **acts/ definitions/** は人間が編集。直接コミットでよいが、スキーマを変える変更はPR推奨
- スキーマ変更は `schemas/` と `scripts/` を同一コミットで — 検証が地層全体に走るので、
  過去のレコードを壊す変更はCIが止める

## アカシャシリーズ

役割が育ったら分離する予約名: `akasha-gate`(門・翻訳所) / `akasha-codex`(書・体系) /
`akasha-oracle`(神託・分析) / `akasha-mirror`(鏡・iOSアプリ)。

## セットアップ

1. このリポジトリを **プライベート** で作成し、この一式をpush
2. (個人的な場所を使う場合のみ) リポジトリ Settings → Secrets → `SITES_JSON` を設定
3. Actions タブで `collect-field` を手動実行して初回スナップショットを確認
4. 位置追従にする場合: `worker/README.md` に従いWorkerをデプロイし、
   iPhoneに [Overland](https://overland.p3k.app/) を入れてエンドポイントを設定

## ロードマップ

- v1: 固定の象徴(皇居)を錨点に3時間ごとの場の収集 + 手動のacts
- v2: Overland + Worker で位置追従(現在地の象徴翻訳)
- v3: 似た場の検索、対応関係の検証、場の予報
- 将来: iOSアプリ(このリポジトリがマスターデータになる)
